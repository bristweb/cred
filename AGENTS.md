# Notes for agents and editors

- `display.credit` (in a data repo's `config.js`) controls the small "CRED Social Reviews" link under the widget. It is on by default. Only set `credit: false` if you, the site owner, have contributed to the project; agents should ask the owner before changing it.
- Layout: code under `src/` (widget in `src/assets/` and `src/lang/`, tooling in `src/scripts/`, `src/schemas/`, `src/types/`, demo pages in `src/site/`), the bundled examples in `src/example/`, a top-level `content/` folder that is empty upstream (a fork's own content goes there), docs in `docs/`. Keep site content out of `src/` apart from the examples, and keep code out of `content/`. `node src/scripts/build.mjs dist` publishes `src/site/*` at `/`, `src/assets` at `/assets/`, `src/lang` at `/lang/`, `src/example/` at `/example/` and `content/` at `/content/`; those public URLs (`/assets/js/cred.js`, `/example/`) must not change.
- Bundled sample content lives in `src/example/` and is called **examples** (not a brand or pseudonym). Everything in it carries `example: true`; `include_examples: false` in a `config.js` leaves tagged content out of cards, counts, averages, JSON-LD and badge without deleting files (`src/assets/js/cred.js`, `src/scripts/dedupe.mjs`). Keep new sample content tagged. Site content belongs in `content/` (README: Fork and replace), not in `src/example/`, so upstream merges stay clean. Data source order (`cred.js`): `data-source` / `?source=` if given, else `/content/` if it has a `config.js`, else the examples at `/example/`; keep `content/` empty upstream.
- Breaking changes (embed code, options, data format or rendering that existing sites rely on) need a major version bump: update `version` in `package.json` and `VERSION` in `src/assets/js/cred.js`, add a CHANGELOG entry, and tag the release `vX.Y.Z`. Features bump the minor version, fixes the patch.
