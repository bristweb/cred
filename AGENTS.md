# Notes for agents and editors

- `display.credit` (in a data repo's `config.js`) controls the small "CRED Social Reviews" link under the widget. It is on by default. Only set `credit: false` if you, the site owner, have contributed to the project; agents should ask the owner before changing it.
- Layout: `src/` is upstream's code and forks leave it alone: widget and defaults in `src/assets/` and `src/lang/`, tooling in `src/scripts/`, `src/schemas/`, `src/types/`, demo host pages in `src/site/`, and `src/example-content/` (a sample of what goes in `content/`). The top-level `content/` folder is the client's: empty upstream (README only), a fork puts everything client-specific there (`config.js`, `reviews/`, `theme/`, `lang/`, `assets/` with `icons/`, `images/` (`images/reviewers/` for avatars), `video/`, `audio/`, and optional `site/` for its own pages and host files). One `assets/` folder sorted by kind; do not add top-level `icons/`, `images/` or `media/` folders anywhere. `docs/` stays top-level. There is no top-level `example/`: `/example/` exists only as a published URL, which the build copies from `src/example-content/`. `src/example-content/` mirrors `content/` exactly (same folder names and nesting); its `site/` folder holds the sample's own host files (`index.html`, `_headers`, `.nojekyll`) and is never published as `/example/site/` or laid over the site root (the build lifts its files to `/example/`). Sample workflows for a standalone data repo live in `docs/data-repo-workflows/`, not in the mirror Do not name the content folder `dist` (generated, git-ignored). Never put client content in `src/` or code in `content/`. `node src/scripts/build.mjs dist` publishes `src/site/*` at `/`, `src/assets` at `/assets/`, `src/lang` at `/lang/`, `src/example-content/` at `/example/`, `content/` at `/content/` and `content/site/*` at `/`; those public URLs (`/assets/js/cred.js`, `/example/`) must not change.
- Bundled sample content lives in `src/example-content/` and is called **examples** (not a brand or pseudonym). Everything in it is example content by location (the widget treats data loaded from `<site root>/example/` as examples; `validate.mjs`/`badge.mjs` treat that folder path the same way), so do not add per-item `example: true` tags there. `include_examples: false` in a `config.js` leaves example content out of cards, counts, averages, JSON-LD and badge without deleting files; in other folders only items tagged `example: true` (optional) count (`src/assets/js/cred.js`, `src/scripts/dedupe.mjs`). Site content belongs in `content/` (README: Fork and replace), not in `src/example-content/`, so upstream merges stay clean. Data source order (`cred.js`): `data-source` / `?source=` if given, else `/content/` if it has a `config.js`, else the examples at `/example/`; keep `content/` empty upstream.
- Breaking changes (embed code, options, data format or rendering that existing sites rely on) need a major version bump: update `version` in `package.json` and `VERSION` in `src/assets/js/cred.js`, add a CHANGELOG entry, and tag the release `vX.Y.Z`. Features bump the minor version, fixes the patch.
